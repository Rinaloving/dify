# 2026-06-18 工作记录

## 图片文字提取功能（OCR）完整实现

### 问题链（按时间顺序）
1. **前端图片不显示** — URL 是相对路径 `/dev/api/File/Image/annex/xxx.png`，正则只匹配 `https?://` → 改正则支持相对路径
2. **Agent 没执行脚本** — Skill 导入时代码还没更新，脚本文件没存到服务器
3. **脚本执行 Exit code 1** — Agent 传 URL，Python 脚本需要本地文件路径
4. **ScriptExecutor 改造** — 加入 `ResolveFilePath()` 方法
5. **JsonElement.RootElement 多写** — 编辑错误 → 改为 `.RootElement`
6. **前端显示被改坏** — 改回 `apiUrl + fileUrl`
7. **中文乱码** — 加 `StandardOutputEncoding = UTF8` + `PYTHONIOENCODING=utf-8`
8. **嵌套 JSON** — Agent 传 `{"input": "{\"file_path\": ...}"}`，脚本支持多层解析
9. **路径写死** — 改为从 C# 注入 `search_dirs` 参数，读框架配置
10. **SSL 错误** — Startup.cs 加 `SecurityProtocolType.Tls12 | Tls13`
11. **依赖安装** — `InstallDependenciesAsync` 改用 `python -m pip install`
12. **OCR 引擎选型** — PaddleOCR 有 oneDNN 兼容问题，最终用 **cnocr**
13. **Skill 详情页** — 列表 API 缺 `skillIds` 字段 → 加到 `AiAppListOutput`

### 最终架构
```
用户上传图片 → 前端显示 API URL → Agent 调用脚本工具
  → C# ScriptExecutor 注入 search_dirs（从 App.json 配置读取）
  → Python 脚本用 cnocr 做中文 OCR
  → 返回提取文字 → LLM 总结回答
```

### 关键文件改动
- **ScriptExecutor.cs** — `ResolveFilePath()` + search_dirs 注入 + UTF8 编码 + FLAGS_enable_pir_api
- **text_extractor.py** — cnocr OCR + 嵌套 JSON 解析 + 文件搜索
- **AiAppListOutput.cs** — 加 `skillIds` 字段
- **AiAppService.cs** — List 查询加 `skillIds`
- **Startup.cs** — TLS 配置

### 关键教训
- URL 到本地路径的转换必须在后端做，不能影响前端显示
- 框架文件存储路径从 `App.json` 的 `SystemPath` 配置读取，不要写死
- PaddlePaddle 新版有 oneDNN/PIR 兼容问题，cnocr 更稳定
- Agent 传给工具的参数可能是嵌套 JSON，脚本要多层解析
- Python 脚本的环境变量要在进程启动前设（C# ProcessStartInfo），不能在脚本里设
